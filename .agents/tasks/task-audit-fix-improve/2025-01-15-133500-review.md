# Comprehensive bug fix, code quality, and UX overhaul for Drawly

This change applies twelve bug fixes, extracts three new modules from a 2500-line Editor component, introduces a toast notification system with confirm dialogs, and adds UX polish (skeleton loading, page transitions, auto-save status indicator, password strength meter). The approach is surface-wide: every page and most hooks/libs are touched, but the core drawing logic and state management remain structurally the same.

Watch for: SVG export still interpolates unsanitized `strokeColor` and `fillColor` into attribute positions (confirmed). The `useAutoSave` hook calls `setStatus` after unmount in the pending-data retry path (likely). The `ConfirmDialog` auto-focuses the destructive "Delete" button rather than the safe "Cancel" button — one accidental Enter press completes a deletion (confirmed). Image cache is never evicted, holding base64 data for deleted elements in memory until Editor unmounts (confirmed).

## High-level view

The Supabase client is now lazily initialized behind a Proxy, deferring client creation until first property access. This solves the crash-on-import problem for tests and SSR, though the `get` trap uses `(client as any)[prop]` — the one remaining `any` in an otherwise tightened type landscape.

Keyboard shortcuts shift from `Ctrl+key` tool bindings (which clashed with browser conventions like Ctrl+A, Ctrl+D, Ctrl+L) to single unmodified keys (`R`, `O`, `D`, `L`, etc.), with Ctrl reserved for operations. The hook reads dynamic state via `useCanvasStore.getState()` at call time — a correct pattern to avoid stale closures without triggering re-subscriptions.

Auto-save fixes the stale-data-on-unmount bug via refs and adds a pending-data queue so changes during an in-flight save are not lost. However, the retry path can fire `setStatus` after unmount.

SVG export escapes text content via `escapeXml`, and `URL.createObjectURL` leaks are plugged. However, element attribute values (colors) and `canvasBg` are still interpolated without escaping into SVG attribute and style positions.

## SVG export: partial XSS mitigation

The `escapeXml` function correctly escapes text node content, closing the original XSS vector. But it is not applied to attribute values:

```typescript
const style = `stroke="${el.strokeColor}" stroke-width="${el.strokeWidth}" fill="${el.fillColor === 'transparent' ? 'none' : el.fillColor}" opacity="${el.opacity}"`
```

If `el.strokeColor` is `" onload="alert(1)`, the resulting SVG has an injected attribute. In practice, colors come from a fixed palette in the UI, so exploitation requires a crafted database record or a manipulated JSON import. The fix is incomplete relative to its stated goal — apply `escapeXml` (or a hex-color validator) to all interpolated attribute values.

The `canvasBg` flows into `style="background:${canvasBg}"` — a separate CSS injection point.

## Auto-save lifecycle and unmount race

The pending-data retry calls `save(pending)` via `setTimeout(0)` after the current save resolves. If the component unmounts between the save completing and the timeout firing, `setStatus('saving')` executes against an unmounted component. React 18 no longer warns, but the update is wasted work. A `mountedRef` flipped in the unmount cleanup would gate these calls.

The `isSaving` return value is read from `isSavingRef.current` at render time — it reflects the value at last render, not current async state. The `status` state is the actual UI driver; `isSaving` is misleading as a public API and could be removed or documented as stale.

## ConfirmDialog: focus on the danger action

The dialog auto-focuses `confirmBtnRef`, which points to the confirm (typically "Delete") button. Standard accessibility guidance (WAI-ARIA dialog pattern) recommends focusing the least destructive action in danger dialogs. Since every current use in this codebase is `variant="danger"`, a user who opens the dialog and presses Enter immediately triggers the deletion.

The `onCancel` prop is an inline arrow function (`() => setConfirmDialog(null)`) creating a new reference every render. It's a dependency of the Escape-key `useEffect`, causing re-registration on every parent render. Not a correctness issue, but a stable-ref pattern would be cleaner.

## Image cache: no eviction

The image cache (`imageCacheRef`) maps `imageData` (base64 strings, potentially megabytes each) to `HTMLImageElement` instances. When elements are deleted from the canvas, their cache entries persist until the Editor component unmounts. A user who imports and deletes many large images will accumulate memory without bound within a session. Evicting entries whose key no longer appears in `elements` (e.g., on a post-delete effect) would bound memory usage.

## Toast accumulation

There is no cap on simultaneous toasts. The API is exposed publicly via `useToast()`, and a future batch operation could push many toasts at once, stacking unbounded DOM nodes. Adding a max-visible limit (e.g., 5) with FIFO dismissal would prevent this.
